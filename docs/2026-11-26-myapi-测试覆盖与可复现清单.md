## 关键可复现场景（含修复的 bug）

### 1. 并发日志不丢（修复：WAL + busy_timeout + INSERT 重试）
```rust
concurrent_50_requests_all_ok / concurrent_100_requests_all_ok
// 断言：100 并发全 200 且 request_logs 恰好 100 条（修复前只记 20~35）
```
**复现**：`cargo test concurrent_100_requests_all_ok`。修复前 SQLite 单写锁丢日志（响应 200 但日志缺）。

### 2. 失败日志记真实上游模型名（修复：requested_model → selected.upstream_model）
```rust
logs_failover_records_upstream_status
// 断言：ch1(up-bad) 500 日志 model=up-bad（修复前记请求别名 my-model）
```
**复现**：`cargo test logs_failover_records_upstream_status`。

### 3. 流式 usage 入库（修复：固定 sleep → wait_summary 轮询）
```rust
stream_mock_openai/anthropic/gemini_usage_recorded
// 断言：usage 值入库（修复前全量并行偶发 flaky）
```
**复现**：`cargo test stream_mock_gemini_usage_recorded`。

### 4. 档位连续切换准确性

## 编写测试时的坑（踩过的，避免再踩）

1. **responses `instructions` 提前变 `system` 消息**：断言上游消息数要算上 system（input 3 条 → 上游 4 条）。
2. **failover 测试 payload 必须匹配到多个候选**：只匹配失败通道 = 无第二候选，failover 不会发生；用共同 `alias`。
3. **失败日志 vs 成功日志 model 字段必须一致**：都记 `selected.upstream_model`（真实上游名）。
4. **异步写日志断言用轮询（wait_summary）**，不用固定 sleep（负载一变就 flaky）。
5. **SQLite 并发写必须 WAL + busy_timeout + 重试**：单请求全过不代表并发安全。
6. **404 是 fatal**（不透传 failover）：全废测试用全 500（retryable）才走 failover 链。
7. **auto 档选任一候选**（不保证具体模型）：断言 auto 用"合法集"，别断言精确模型。
