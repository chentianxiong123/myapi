# 上下文窗口：网关全责界定，客户端无感

> 方向（用户拍板）：**上下文窗口全部在网关界定，绕开客户端差异性。网关全功能责任，负责看上下文给模型，下游无感。**
> 客户端不做（不截断、不重试、不感知 context）。网关全模型都试，**全废了才反馈错误给客户端**。

## 一、核心决策

**客户端不能做上下文管理。** 网关要彻底：
```
客户端发请求（无感，不截断不重试）
  → 网关试第 1 个通道 → context 报错（不是 fatal）
  → 网关试第 2 个 → 报错
  → ... 全模型都试完
  → 全废了 → 才给客户端错误（真废了）
```
**客户端只有在"所有模型都接不了"时才收到错误**——任何模型能接，客户端就无感。

## 二、为什么不做估算（性能优先）

| 方案 | 运行时成本 | 决策 |
|---|---|---|
| 精确估算请求 token | 高（tokenizer/遍历所有 content） | ❌ **否决**——长期牺牲性能的事不做 |
| 静态 `context_window` 标注 | **零**（配置时填，运行时只比较整数） | ✅ 采用 |
| 错误反馈（报错才决策） | 零（只在出错时） | ✅ 采用 |

**网关有所有模型的 `context_window` 标注，但不预先量请求**——报错了才决策。这是"错误反馈驱动"，不是"估算驱动"。

## 三、实现要点（复用现有 fallback，改动集中）

### 1. `ChannelModel.context_window` 标注（配置时填）
```yaml
providers:
  - channels:
      - models:
          - name: deepseek-v4-flash
            context_window: 128000   # 配置时填，运行时零成本
```
网关是**唯一界定处**——客户端不填、不看、不感知。

### 2. context 关键词词表（学现有 `hit_disable_keyword`）
```
context_length_exceeded
maximum context length
exceeds the maximum
too many tokens
```
与欠费/封号关键词并列，复用同一套检测机制。

### 3. 错误分类改造
现在 `context_length_exceeded`（400）走 **fatal**（`def_fatal_status=[400,...]`）→ 直接透传，不换通道。
改为：**context 关键词命中 → Retryable**（可换通道），**不算普通失败**。

### 4. fallback 全试（豁免 max_retries）
- context 报错**豁免 `max_retries`**（不是普通失败，不占重试次数）
- 继续试下一个候选，**候选耗尽才透传错误**给客户端
- 换通道顺序：保持现有候选链（按路由策略：延迟/权重/黏性），顺延下一个；**不做 context 降序重排**（避免为"猜哪个大"做复杂逻辑）

## 四、现状（缺口）

| 项 | 现状 | 缺 |
|---|---|---|
| 模型 context 标注 | `Channel.max_input_tokens`（通道级，`ordered_candidates` 过滤） | **模型级 `context_window` 缺** |
| context 错误分类 | 400 默认 fatal → 透传 | **改成 Retryable + 豁免 max_retries** |
| 关键词机制 | `hit_disable_keyword`（欠费/封号）→ 熔断切通道 | **加 context 词表** |

**已有基础**（复用）：
- `def_fatal_status = [400,401,403,404]` → 400 现 fatal，需改
- `hit_disable_keyword`（行 780）+ `def_disable_keywords`（行 60）→ 加 context 词
- `forward_generic` fallback 循环（行 1213+）→ context 报错豁免 max_retries
- `retry.disable_keywords` 配置 → 可扩展 context 关键词

## 五、客户端无感的边界（诚实）

- 客户端（codex/claude）**自己本来就有 context 管理**（截断/压缩）。网关全责后，这些客户端行为照旧存在，但**客户端不知道模型的窗口**——它只管发。
- 网关**只选模型**（选窗口够的），**不截断请求内容**。截断是内容管理，网关不做（避免与客户端自身截断双重处理、丢信息）。
- **"真废了才报错"** = 所有候选通道都 context 装不下（或熔断/不可用）→ 透传最后错误。

## 六、一句话
**客户端无感，网关全试；context_window 静态标注（零成本），错误反馈驱动（报错换通道）；全模型都废了才反馈客户端。**
