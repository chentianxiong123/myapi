# 思考模式——同识图待遇（capability 声明 + 硬约束 + 协议映射）

> 2026-11-26。用户拍板：**思考模式要跟识图模式（vision）一个待遇**——模型适不适合思考要显式声明（capability），请求需要时**硬约束**（无能力→409 显式失败，不静默降级），前端有配置入口。
> 协议映射学 cc-switch（`transform.rs` / `thinking_optimizer.rs` / `transform_codex_anthropic.rs`），能力约束复用 vision 硬约束链路。

## 1. 如何配（同 vision）

**前端**（Providers 页 → 模型编辑）：`capabilities` 多选框新增 **`thinking`**（原 vision/pdf/audio）。

**gateway.yaml**：
```yaml
providers:
  - channels:
      - models:
          - name: deepseek-r1        # 上游真实模型名
            alias: auto              # 客户端档位名
            capabilities: [thinking] # 声明支持思考模式（同 vision 声明）
```

**语义**：
- `capabilities: [thinking]` = 模型适不适合思考（能力声明）
- 缺 `thinking` = 不适配思考请求（带思考参数的请求会被过滤/409）

## 2. 硬约束（同 vision，不静默）

| 场景 | 行为 |
|------|------|
| 请求带思考参数 + 模型有 thinking | 候选通过，正常转发 |
| 请求带思考参数 + 模型无 thinking | **HTTP 409 `capability_unavailable`**（显式失败，不静默降级） |
| 请求带 `thinking:{type:"disabled"}` | **不算需求**（客户端明确关，无 thinking 模型也 200） |
| 请求不带思考参数 | 不要求（模型无 thinking 也 OK） |

**完整链路**（自动复用 vision 硬约束）：
```
detect_required_caps(payload) → ["thinking"]
→ ordered_candidates(..., &required) 过滤（无 thinking 候选剔除）
→ 候选空 + 模型存在 → 409 capability_unavailable（{"required": ["thinking"]}）
```

## 3. 协议映射（三协议，请求方向）

| 客户端协议 | 思考参数 | 网关检测 | 上游转发 |
|-----------|---------|---------|---------|
| anthropic（/v1/messages）| `thinking:{type,budget_tokens}` | detect_required_caps → thinking | chat: `reasoning_effort`；anthropic 上游: `thinking` 透传 |
| responses（/v1/responses）| `reasoning:{effort}` | detect_required_caps → thinking | chat: `reasoning_effort` |
| chat（/v1/chat/completions）| `reasoning_effort` | detect_required_caps → thinking | chat: 透传；anthropic 上游: `thinking` |

## 4. 协议转换精细映射（学 cc-switch）

### anthropic `thinking` → chat `reasoning_effort`（resolve_reasoning_effort）
- **thinking 是对象** `{type,budget_tokens}`（**不是数组**——早期 bug：用 `.as_array()` 遍历识别不到思考，已修）
- **Priority 1**：`output_config.effort`（low/medium/high/xhigh/max）
  - `max` 仅支持模型的模型保留，否则回退 `xhigh`
  - 思考 off（省略或 disabled）→ effort floor 到 `low`
- **Priority 2**：`thinking.type` + `budget_tokens`
  - `adaptive` → `xhigh`（Claude 5.x 默认，最大推理）
  - `enabled` + <4000 → `low`；<16000 → `medium`；其余 → `high`；无 budget → `high`
  - `disabled`/缺失 → `None`
- **Claude 5.x 省略 thinking = adaptive 默认**（fable-5/mythos-5/mythos-preview/opus-5/sonnet-5）——不 floor low
- **模型感知 clamp**：`gpt-5-pro` → 强制 `high`；其他 `gpt-*-pro` → 最低 `medium`

### chat `reasoning_effort` → anthropic 上游 `thinking`（chat_to_anthropic_request）
- budget 对齐 cc-switch `effort_to_thinking_budget`：minimal/low→2048、medium→8192、high→16384、xhigh/max/ultra→24576

### chat `reasoning_effort` → responses `reasoning` 项（chat_to_responses）
- `reasoning_content` → `reasoning` 项（`summary:[summary_text]`）

## 5. 流式转换

| 方向 | 处理 |
|------|------|
| chat SSE → anthropic SSE | `reasoning_content` → `thinking_delta`（AnthropicSseState）|
| chat SSE → responses SSE | `reasoning_content` → `reasoning_summary_text.delta` + item added/done（ResponsesSseState，**早期缺，已补**）|
| anthropic SSE → chat SSE | `thinking_delta` → `reasoning_content`（AnthropicUpstreamSseState）|

## 7. 已知边界 / 未做

- **思考强度**（effort 等级）：目前是 capability 有/无（同 vision）；模型具体支持的 effort 档次（如只支持 low/medium）未建模（cc-switch 有 `reasoningLevels`，myapi 无 modelCatalog 声明）
- **工具轮 thinking 历史规范化**（DeepSeek 等需 plain thinking 块的 provider）未做（cc-switch 有 `normalize_anthropic_tool_thinking_history_for_provider`）
- **thinking:disabled + reasoning_effort 互斥 400** 未做（cc-switch `normalize_deepseek_thinking_disabled_strip_effort`）
- 以上需 provider 特定逻辑或模型声明，myapi 无此概念，按"不抄企业级/不过度设计"暂缓
