# 档位路由（Tier Routing）——设计与实现

> 状态：网关 + 客户端下发已实现并通过测试（172 passed）。
> 关键：`auto`/`pro`/`flash` 是**客户端配置的 model 名**，不是网关内部概念。

## 一、档位语义：塌缩程度

普通用户切换模型 = 改配置字符串。档位是**客户端配置的 model 名**，网关据此选真实模型。

| 档位 | 塌缩程度 | 候选范围 | 语义 |
|------|---------|---------|------|
| `auto` | 塌缩成 1（自由） | 全部模型 | 网关随意选一个可用的 |
| `pro` | 塌缩成质量型 | 只 `class: pro` | 质量优先 |
| `flash` | 塌缩成速度型 | 只 `class: flash` | 速度优先 |

模型侧标注档位（`ChannelModel.class`），对标 Gemini 的 pro/flash 区分：

```yaml
channels:
  - models:
      - { name: gemini-pro,   class: pro }    # 质量型
      - { name: gemini-flash, class: flash }  # 速度型
      - { name: some-model }  # 无标注 → 只进 auto
```

## 二、网关档位路由（`rs/src/gateway.rs`）

### 2.1 档位识别

```rust
let is_tier = requested_model == "auto" || requested_model == "pro" || requested_model == "flash";
```

档位名是**保留字**，优先于模型名匹配。约定：**模型名不能叫 `auto`/`pro`/`flash`**。

### 2.2 候选硬过滤

`auto_candidates(config, payload, health, class_filter)`：

| 请求档位 | `class_filter` | 候选 |
|---------|---------------|------|
| `auto` | `None` | 全部（含无标注模型） |
| `pro` | `Some("pro")` | 只 `class: pro` |
| `flash` | `Some("flash")` | 只 `class: flash` |

```rust
if let Some(cf) = class_filter {
    if m.class.as_deref() != Some(cf) { continue; }
}
```

过滤与能力硬约束（`required`）**同时生效**：`pro` 档位只从 `class: pro` 的模型里选满足能力的候选。

### 2.3 边界行为

- **档位候选为空** → HTTP 404 `"pro: 无可用模型"`（不降级到全部，档位是硬边界）
- **带硬需求（当前轮带图）但无满足能力** → HTTP 409 `capability_unavailable`（显式失败，不静默）
- **档位内 failover**：候选逐个试，失败的切下一个（复用既有 failover 链）
- `auto` 需 `auto_mode_enabled`；`pro`/`flash` 不受该开关控制（档位是显式意图）

## 三、客户端档位映射（adapter 下发）

客户端 adapter 下发档位名到客户端配置，让档位路由生效。

### 3.1 Claude Code（`adapters/claude.rs`）

Claude Code 内置任务分档（opus/sonnet/haiku/fable），映射到 myapi 档位：

| Claude Code 档位 | → myapi 档位 | 理由 |
|-----------------|-------------|------|
| `ANTHROPIC_DEFAULT_OPUS_MODEL` | `pro` | 质量档，Claude Code 把复杂任务派给它 |
| `ANTHROPIC_DEFAULT_FABLE_MODEL` | `pro` | 同上（质量型） |
| `ANTHROPIC_DEFAULT_SONNET_MODEL` | `auto` | 默认档 |
| `ANTHROPIC_MODEL` | `auto` | 默认档 |
| `ANTHROPIC_DEFAULT_HAIKU_MODEL` | `flash` | 轻量档 |
| `CLAUDE_CODE_SUBAGENT_MODEL` | `flash` | 子代理任务轻量 |

**之前的问题**：所有档位变量都填同一个模型 id（塌缩成 1），Claude Code 的任务分档失效。

### 3.2 Codex（`adapters/codex.rs`）

Codex 只有单档位（一个 `model` 配置）：

- `model = "auto"`、`review_model = "auto"`、`modelCatalog.model = "auto"`
- 不再按模型循环生成 provider（原来每模型一个重复 provider）
- 用户可手动改 `config.toml` 的 `model = "pro"`/`"flash"` 切档位

### 3.3 openclaw（`adapters/openclaw.rs`）

`models` 列表下发 3 个档位（`auto`/`pro`/`flash`），客户端从档位选。

### 3.4 omp（`adapters/omp.rs`）

`providers.myapi.models` 下发 3 个档位。

**注意**：omp 模型 id 格式是 `provider/model`（如 `cpa/auto`），白名单用通配符（`cpa/*`）匹配，因此**不改** `enabledModels` 白名单逻辑（加裸档位名会污染白名单且不匹配）。

## 四、关键决策

### 4.1 日志记真实上游模型名

```rust
// gateway.rs forward_one（流式 + 非流式）
model: selected.upstream_model.clone(),  // 真实上游模型名，非档位别名
```

用户明确要求：**日志不能只记 `auto`/`pro` 档位别名，要记真实上游模型名**。用量分析按真实模型统计。

### 4.2 响应 body 的 `model` 字段回显档位名

```rust
let body_bytes = if requested_model == "pro" || requested_model == "flash" || requested_model == "auto" {
    // 改 body["model"] = 档位名
} else { body_bytes };
```

理由：对称于客户端配的 model 名。客户端（如 Claude Code）用它配置的 model 名做内部判断（上下文窗口等），回真实模型名会让它按未知模型处理。真实模型名已在日志记录。

> ⚠️ 这是合理默认（对称），**待用户最终确认**。

### 4.3 不降级

档位候选全不可用时返回 404，不降级到 `auto` 全部。档位是用户显式意图（"我要质量型"），静默降级到速度型违反意图。
