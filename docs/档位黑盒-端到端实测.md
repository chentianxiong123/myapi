## 三、对齐 cc-switch 的做法

| 机制 | cc-switch 做法 | myapi 对齐 |
|------|---------------|-----------|
| Claude `[1M]` 后缀 | 模型名带 `[1M]`（MODEL 带、MODEL_NAME 不带），代理层 `strip_one_m_suffix` 剥离 | `strip_1m_suffix`（网关剥离）+ claude 档位名带 `[1M]` |
| Codex modelCatalog | `model_catalog_json` 列模型 + metadata，codex 据此认识 | 网关 `/v1/models` 返回 3 档位名；adapter modelCatalog 3 档位（`['model','displayName']` 对齐 cc-switch 真实格式） |
| 档位（黑盒） | 档位从 modelCatalog resolve | 网关黑盒：档位识别 + `class` 硬过滤 + 能力/健康度/failover |

## 五、关键决策（用户拍板）

1. **所有客户端只收到 3 个模型名**：`auto`/`pro`/`flash`（无论哪个客户端）
2. **一切调度在网关黑盒**：客户端发档位名，网关选真实模型（能力/健康度/failover 全在网关）
3. **日志记真实模型名**（非档位别名）
4. **响应 model 回显档位名**（对称客户端配置）
5. **不恢复原配置**：claude/codex 指向 myapi 网关
